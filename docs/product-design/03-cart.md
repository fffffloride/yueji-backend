# 购物车模块产品设计说明

> 模块状态：服务端 C 端能力已实现；小程序购物车页面待接入

## 1. 模块定位、目标与非目标

购物车模块为已登录会员暂存待购买规格、数量和选中状态，并将选中的购物车项交给订单模块结算。

目标：

- 同一会员、同一规格只保留一条有效购物车记录。
- 加购、改数量时遵守实时库存。
- 购物车能识别商品或规格已经失效的项目。
- 从购物车创建订单后移除已结算项目。

非目标：

- 不承担商品价格或库存维护。
- 不负责优惠试算、订单创建、支付或核销。
- 当前没有跨设备离线合并、购物车营销提示或凑单推荐。

## 2. 用户角色、场景与端侧范围

| 角色     | 使用场景                             | 当前支持                     |
| -------- | ------------------------------------ | ---------------------------- |
| 会员     | 加入购物车、查看、改数量、选中和删除 | 服务端已实现，C 端页面待接入 |
| 运营人员 | 无购物车管理场景                     | 不提供 B 端页面              |

## 3. 核心业务对象与术语

- **购物车项**：会员选择的一个商品规格及其数量、选中状态。
- **选中状态**：表示该购物车项是否计划进入本次结算。
- **失效项**：商品或规格不存在、已删除、已下架或已停用的购物车项。
- **合并加购**：会员重复加入同一规格时，在原数量上累加，而非创建重复行。

## 4. 功能清单

### 4.1 C 端

- 查看本人购物车，并按最近更新时间倒序展示。
- 查看商品名称、图片、规格名称、当前价格、当前库存、数量、选中状态和失效标记。
- 加入指定规格和数量。
- 重复加购同一规格时自动合并数量并重新设为选中。
- 修改数量，单次允许 1–99 件且不能超过当前库存。
- 修改选中或未选中状态。
- 删除本人购物车项。
- 选择购物车项进入订单试算与创建。

### 4.2 B 端

当前不提供购物车查询或代客编辑能力。

## 5. 关键用户流程

### 5.1 加入购物车

1. 会员在商品详情选择启用规格和数量。
2. 系统确认商品、规格可售，并读取当前库存。
3. 若购物车已有同一规格，则累加数量；否则新增购物车项。
4. 累加后的总数量不能超过库存。
5. 加购成功后，该项自动为选中状态。

### 5.2 从购物车结算

1. 会员进入购物车，查看最新价格、库存和失效状态。
2. 会员选择要购买的有效购物车项。
3. 进入订单确认时，系统再次检查购物车归属、商品状态、规格状态和库存。
4. 订单创建成功后，仅删除本次参与结算的购物车项。
5. 未选中或未参与结算的项目继续保留。

## 6. 业务规则与状态

- 购物车仅对已登录会员开放。
- 每条购物车项只能属于一个会员，会员不能读取或操作他人的购物车项。
- 同一会员的同一规格执行合并加购。
- 加购和改数量时上限为 99，同时不能超过实时库存。
- 购物车显示当前规格价格，不冻结加购时价格。
- 商品或规格失效后，购物车项保留并标记失效，便于用户识别；失效项不能进入有效订单。
- 购物车项的选中状态只表示结算意愿，不代表库存已锁定。
- 库存在订单创建成功时扣减，购物车阶段不预占库存。

## 7. 权限与数据可见范围

- 会员只能查看、修改和删除本人购物车项。
- 使用非本人购物车项发起结算时，统一按购物车项不存在处理。
- B 端不提供查看会员购物车的入口。

## 8. 异常与边界场景

| 场景                         | 处理                                                       |
| ---------------------------- | ---------------------------------------------------------- |
| 商品或规格已下架/停用        | 购物车中标记失效，不能正常结算                             |
| 加购后总数量超过库存         | 拒绝加购并提示库存不足                                     |
| 修改数量超过库存             | 拒绝修改并保留原数量                                       |
| 操作不存在或非本人购物车项   | 提示购物车项不存在                                         |
| 结算期间同一购物车被重复提交 | 仅首个有效创建继续，后续请求提示购物车项不存在或状态已变化 |
| 购物车为空或未选择商品       | 不允许进入有效下单流程                                     |

## 9. 模块联动

- [商品模块](./02-product.md)提供规格有效性、实时价格与库存。
- [订单模块](./04-order.md)负责试算、重新校验、扣库存和创建订单。
- 订单创建成功后，订单模块通知购物车移除已结算项目。

## 11. 验收标准

- **Given** 会员购物车已有某规格 2 件，**When** 再加购 1 件且库存充足，**Then** 原购物车项数量变为 3 且保持选中。
- **Given** 加购后的总数量超过库存，**When** 提交加购，**Then** 系统拒绝并提示库存不足。
- **Given** 商品已下架，**When** 会员查看购物车，**Then** 对应项目保留并标记失效。
- **Given** 会员提交他人的购物车项，**When** 修改、删除或结算，**Then** 系统按项目不存在拒绝操作。
- **Given** 订单从三个购物车项中的两个创建成功，**When** 返回购物车，**Then** 已结算两项被移除，另一项继续保留。
