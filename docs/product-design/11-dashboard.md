# 经营看板模块产品设计说明

> 模块状态：服务端与 B 端已实现；小程序访问上报能力已具备，初始化接线待确认

## 1. 模块定位、目标与非目标

经营看板为后台首页提供访问趋势、会员概览、业务待办和系统动态，让运营人员快速了解当天运行情况并进入对应业务处理页面。

目标：

- 记录匿名小程序访客的每日访问量和浏览量。
- 展示今日访问、会员总数及环比信息。
- 汇总当前需要处理的订单、代理、提现和退款事项。
- 聚合近期关键业务动态并提供跳转入口。

非目标：

- 当前不提供营业额、订单转化率、商品排行、渠道归因或用户路径分析。
- 不替代分销销售统计，销售额口径归[分销模块](./10-distribution.md)的销售分析部分。
- 不提供自定义看板、指标配置或任意日期范围分析。

## 2. 用户角色、场景与端侧范围

| 角色         | 使用场景                           | 当前支持                         |
| ------------ | ---------------------------------- | -------------------------------- |
| 后台运营人员 | 登录后台后查看今日概览和近期趋势   | B 端已实现                       |
| 业务处理人员 | 从待办直接进入订单、代理或结算页面 | B 端已实现                       |
| 小程序访客   | 无感产生匿名页面访问记录           | 上报工具已实现，初始化接线待确认 |

## 3. 核心业务对象与术语

- **访客标识**：小程序本地生成并持久保存的匿名标识，不等同于会员身份。
- **UV**：同一自然日在本设备访客标识维度去重后的访客数。
- **PV**：页面访问总次数，同一访客多次访问会累计。
- **待办**：当前满足待处理条件的业务记录。
- **今日新增待办**：当天新进入待办处理范围的记录数量。
- **今日已处理**：当天完成对应处理动作的记录数量。
- **系统动态**：近期后台操作及核心业务事件的时间流。

## 4. 功能清单

### 4.1 顶部概览

- 展示后台当前在线人数及实时连接状态。
- 展示今日访客数及相对昨日增长率。
- 展示今日浏览量及相对昨日增长率。
- 展示正常会员总数、今日新增和相对昨日新增增长率。

### 4.2 访问趋势

- 支持近 7 天和近 30 天切换。
- 同图展示每日浏览量和访客量。
- 没有访问数据的日期补 0，保持连续时间轴。

### 4.3 待办概览与事项

- 汇总当前待办总数、今日新增和今日已处理。
- 按订单核销、代理审核、提现审核、提现打款、退款异常分类展示。
- 展示最近 5 条待办的标题、状态、发生时间和目标页面。
- 点击待办跳转至对应业务页面。

### 4.4 系统动态

- 展示最近 10 条关键动态。
- 动态来源包括后台操作、会员注册、订单创建/支付/核销/取消、退款、预约、代理申请/审核、提现创建/审核/打款和系统通知发布。
- 有目标页面的动态支持点击跳转。

## 5. 关键用户流程

### 5.1 访问上报与趋势形成

1. 小程序首次需要上报时生成匿名访客标识并保存在本地。
2. 页面导航成功后尝试上报当前访客的一次访问。
3. 同一访客同一天首次访问形成一个 UV，并累计一次 PV。
4. 同一天后续访问只增加 PV，不重复增加 UV。
5. 上报失败被静默忽略，不阻断用户页面跳转。
6. 后台按近 7 天或近 30 天读取连续趋势。

### 5.2 待办处理

1. 后台用户打开经营看板。
2. 系统从当前业务状态计算待办数量和最近事项。
3. 用户点击待办进入对应业务页面。
4. 完成核销、审核、打款或退款处理后，再次刷新看板。
5. 已不符合待办条件的记录从当前待办移除，并计入相应的今日已处理口径。

## 6. 业务规则与状态

### 6.1 访问统计

- 统计日期按 Asia/Shanghai 自然日计算。
- UV 按“日期 + 匿名访客标识”去重。
- PV 为该访客当日成功上报次数累计。
- 小程序端对同一路由 500 毫秒内的重复导航结果做一次简单去重。
- 今日与昨日比较时，昨日值为 0 则增长率显示为不可计算，不展示虚假百分比。

### 6.2 会员概览

- 会员总数只统计正常且未删除会员。
- 今日新增和昨日新增按会员创建日期统计。
- 今日新增相对昨日新增计算增长率；昨日新增为 0 时不展示百分比。

### 6.3 待办口径

| 分类     | 当前待办条件                   | 处理完成条件               |
| -------- | ------------------------------ | -------------------------- |
| 订单核销 | 订单为待核销                   | 订单完成核销               |
| 代理审核 | 代理申请为待审核               | 审核通过或驳回             |
| 提现审核 | 提现单为待审核                 | 审核通过或驳回             |
| 提现打款 | 提现单为待打款                 | 确认已打款                 |
| 退款异常 | 退款失败，或处理中超过 30 分钟 | 退款成功或不再满足异常条件 |

- 待办总数为五类当前待办数量之和。
- 最近待办跨分类按发生时间倒序取 5 条。
- 退款超时阈值当前固定为 30 分钟。

### 6.4 系统动态

- 不单独复制业务数据，而是从当前后台日志和核心业务记录聚合。
- 跨来源按事件发生时间倒序取最近 10 条。
- 没有目标页面的后台操作动态只展示，不执行跳转。

## 7. 权限与数据可见范围

- 经营看板数据需要后台看板查看权限。
- 后台在线人数来自实时会话能力，不使用会员在线口径。
- 访问上报为公开能力，但只接受符合格式的匿名访客标识。
- 看板展示摘要和最近事项，不替代各模块的详细权限；跳转后仍需通过目标页面权限校验。

## 8. 异常与边界场景

| 场景                         | 处理                     |
| ---------------------------- | ------------------------ |
| 某日没有访问记录             | 趋势补 0，不中断折线     |
| 昨日 UV、PV 或新增会员为 0   | 增长率显示为不可计算     |
| 小程序上报失败               | 静默忽略，不影响页面访问 |
| 访客标识格式无效             | 拒绝记录该次访问         |
| 当前没有待办或动态           | 展示空状态               |
| 用户能看见待办但无目标页权限 | 跳转后由目标模块拒绝访问 |
| 关联业务表暂无数据           | 对应指标和分类显示 0     |

## 11. 验收标准

- **Given** 同一访客当天连续访问三个页面，**When** 三次上报成功，**Then** 当日 UV 增加 1、PV 增加 3。
- **Given** 近 7 天中某日没有访问，**When** 查看趋势，**Then** 该日 UV/PV 均展示 0 且时间轴连续。
- **Given** 当前存在待核销订单、待审核代理和待打款提现，**When** 打开看板，**Then** 三类数量正确计入待办总数。
- **Given** 用户完成一笔订单核销，**When** 刷新看板，**Then** 该订单从当前待办移除并出现在近期动态中。
- **Given** 访问上报失败，**When** 用户执行页面跳转，**Then** 页面仍正常打开且不显示阻断错误。
