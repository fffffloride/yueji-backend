# 商品模块产品设计说明

> 模块状态：服务端、B 端和 C 端商品浏览均已实现

## 1. 模块定位、目标与非目标

商品模块维护医美服务商品的分类、展示信息、销售规格、价格和库存，是购物车、订单、优惠券和拼团的商品来源。

目标：

- 运营人员可维护最多三级的商品分类树。
- 商品支持一个商品主体和多个销售规格。
- C 端只展示有效分类、已上架商品和已启用规格。
- 交易发生时以系统当前有效规格、价格和库存为准。

非目标：

- 购物车和结算行为归[购物车](./03-cart.md)与[订单](./04-order.md)模块。
- 营销优惠归[营销模块](./06-marketing.md)。
- 拼团价及活动时间归[拼团模块](./09-group-buy.md)。

## 2. 用户角色、场景与端侧范围

| 角色         | 使用场景                                 | 当前支持   |
| ------------ | ---------------------------------------- | ---------- |
| 游客/会员    | 浏览分类、搜索商品、筛选、排序和查看详情 | C 端已实现 |
| 商品运营人员 | 维护分类、商品、规格、库存和上下架       | B 端已实现 |

## 3. 核心业务对象与术语

- **分类**：用于组织商品的树形目录，最多三级。
- **商品**：承载名称、副标题、图片、视频、标签、详情和产品说明的展示主体。
- **规格**：实际可销售的商品单位，拥有独立名称、价格、原价、库存和启停状态。
- **商品现售价**：该商品所有启用规格中的最低售价。
- **商品库存**：该商品所有启用规格库存之和。
- **疼痛友好**：用于 C 端商品目录筛选的商品标签属性。

## 4. 功能清单

### 4.1 B 端分类管理

- 查看包含启用和禁用分类的完整分类树。
- 新建、编辑、启用、禁用和删除分类。
- 设置上级分类、名称、图标、排序和状态。

### 4.2 B 端商品管理

- 按商品名称、分类和上下架状态筛选。
- 新建和编辑商品基础展示信息。
- 为商品维护一个或多个规格及其售价、原价、库存和状态。
- 查看商品分类、标签、疼痛友好标识、最低售价、销量、库存和上下架状态。
- 单独执行商品上架或下架。
- 删除没有受保护交易引用的商品。

### 4.3 C 端商品浏览

- 查看启用分类树。
- 按名称搜索商品，按分类（含子分类）筛选。
- 按标签筛选推荐、新品、热卖等商品。
- 支持综合、销量、价格升序、价格降序和新品排序。
- 查看连续商品目录，并可只看疼痛友好商品。
- 查看商品主图、轮播图、视频、规格、价格、库存、详情和产品说明。

## 5. 关键用户流程

### 5.1 商品上架

1. 运营人员选择有效分类并填写商品展示信息。
2. 至少添加一个规格，维护售价和库存。
3. 若选择直接上架，至少需要一个启用规格。
4. 保存后系统计算商品最低售价和启用规格库存总量。
5. 上架商品进入 C 端商品列表和详情浏览范围。

### 5.2 用户浏览商品

1. 用户从产品中心查看启用分类和商品目录。
2. 用户使用分类、关键词、标签、疼痛友好或排序条件缩小范围。
3. 用户进入商品详情并选择仍然启用且有库存的规格。
4. 后续加购或立即购买交由购物车或订单模块处理。

## 6. 业务规则与状态

### 6.1 分类规则

- 分类最多支持三级。
- 分类不能把自己设置为上级，也不能移动到自己的子分类下。
- 存在子分类时不能变更父级，避免整棵分类树产生不一致。
- 存在子分类或归属商品时不能删除分类。
- B 端展示全部有效记录；C 端只展示启用分类。
- 分类按排序值升序展示，同排序时保持稳定顺序。

### 6.2 商品与规格规则

- 每个商品至少有一个规格。
- 售价、原价和库存不能为负数。
- 商品上架时必须至少有一个启用规格。
- 商品最低售价和总库存只计算启用规格。
- C 端商品详情只返回启用规格；下架商品或停用规格不可购买。
- 商品销量在支付成功后增加，整单退款后回退，最低不小于 0。
- 删除商品或移除规格前，需要确认没有待付款、待核销或已核销交易继续引用。

### 6.3 状态

| 对象 | 状态 | C 端表现               |
| ---- | ---- | ---------------------- |
| 分类 | 启用 | 可作为浏览和筛选目录   |
| 分类 | 禁用 | 不在 C 端分类树中展示  |
| 商品 | 上架 | 可进入列表、目录和详情 |
| 商品 | 下架 | C 端不可浏览或购买     |
| 规格 | 启用 | 可选择和购买           |
| 规格 | 停用 | 不作为可售规格展示     |

## 7. 权限与数据可见范围

- 商品分类与商品的新增、编辑、上下架、删除分别受后台权限控制。
- C 端商品浏览为公开能力，不要求会员登录。
- C 端不展示内部删除标识或禁用对象。
- 商品运营人员不能通过端侧提交值绕过库存和可售状态检查。

## 8. 异常与边界场景

| 场景                            | 处理                           |
| ------------------------------- | ------------------------------ |
| 上架商品没有启用规格            | 拒绝上架并提示至少启用一个规格 |
| 访问下架商品详情                | 提示商品不存在或已下架         |
| 选择停用规格                    | 提示规格不存在或已停用         |
| 购买数量超过库存                | 拒绝继续并提示库存不足         |
| 删除有子分类的分类              | 拒绝删除                       |
| 删除仍有商品的分类              | 拒绝删除                       |
| 删除被进行中订单引用的商品/规格 | 拒绝操作并保留交易完整性       |
| 筛选结果为空                    | 展示空状态，不回退展示无关商品 |

## 9. 模块联动

- [购物车模块](./03-cart.md)读取商品与规格的实时价格、库存和有效性。
- [订单模块](./04-order.md)在试算和创建时重新检查可售状态，并在创建、取消和退款时调整库存。
- [营销模块](./06-marketing.md)按商品或分类范围判断优惠券是否可用。
- [拼团模块](./09-group-buy.md)绑定单一规格，并要求拼团价低于规格售价。

## 11. 验收标准

- **Given** 分类已有子分类，**When** 运营人员尝试更换其父级或删除，**Then** 操作被拒绝并说明原因。
- **Given** 商品没有启用规格，**When** 尝试上架，**Then** 商品不能进入上架状态。
- **Given** 商品已上架且有多个启用规格，**When** 查看列表，**Then** 现售价为最低规格价、库存为启用规格库存之和。
- **Given** 用户按父分类筛选，**When** 子分类下存在上架商品，**Then** 商品出现在筛选结果中。
- **Given** 商品或规格已停用，**When** 用户访问详情或发起购买，**Then** 系统拒绝使用该商品或规格。
