# 会员模块产品设计说明

> 模块状态：服务端与 B 端已实现；C 端资料能力已实现，小程序页面待接入

## 1. 模块定位、目标与非目标

会员模块承载小程序消费者的业务身份和基础资料，为购物车、订单、营销、预约、拼团及分销提供统一会员主体。

目标：

- 会员首次成功登录后形成唯一会员身份。
- 会员可查看和维护本人基础资料。
- 运营人员可查询会员、维护运营标签与备注，并查看会员消费概览。

非目标：

- 登录凭证、Token 和微信登录过程属于认证能力，不在本模块展开。
- 会员等级、积分、优惠券规则归[营销模块](./06-marketing.md)。
- 代理身份及团队关系归[分销模块](./10-distribution.md)。

## 2. 用户角色、场景与端侧范围

| 角色         | 使用场景                         | 当前支持                   |
| ------------ | -------------------------------- | -------------------------- |
| 会员         | 查看资料，修改昵称、头像和性别   | 能力已实现，C 端页面待接入 |
| 运营人员     | 查询会员列表、查看详情和消费概览 | B 端已实现                 |
| 会员运营人员 | 为会员维护标签和内部备注         | B 端已实现                 |

## 3. 核心业务对象与术语

- **会员**：小程序消费者的业务身份，与后台系统用户相互独立。
- **微信身份**：会员首次登录时用于识别同一自然用户的微信标识。
- **会员资料**：昵称、头像、性别、手机号、注册时间和最后登录时间等信息。
- **运营标签**：运营人员为会员添加的逗号分隔标签，仅供后台使用。
- **运营备注**：后台人员记录的内部说明，不向会员展示。
- **会员 360° 视图**：会员资料、消费统计和最近订单的聚合视图。

## 4. 功能清单

### 4.1 B 端

- 按昵称或手机号关键字搜索会员。
- 按正常、禁用状态筛选会员。
- 展示会员昵称、头像、手机号、积分、状态、注册时间和最后登录时间。
- 查看会员详情和 360° 视图。
- 查看订单总数、有效支付订单数、累计有效实付、平均有效实付和各状态订单数量。
- 查看最近 10 笔订单及其订单号、状态、实付金额和下单时间。
- 编辑运营标签与运营备注。

### 4.2 C 端

- 查看本人昵称、头像、性别、手机号、积分和等级关联等资料。
- 修改本人昵称、头像和性别。
- 手机号由手机号登录流程绑定，不能通过普通资料编辑直接修改。

## 5. 关键用户流程

### 5.1 首次形成会员身份

1. 用户通过微信登录完成身份校验。
2. 系统按微信身份查找会员。
3. 未找到时创建新会员，初始昵称为“微信用户”、状态为正常、积分与累计实付为 0。
4. 若存在启用且门槛为 0 的默认等级，则新会员关联该等级。
5. 系统记录本次最后登录时间。

### 5.2 运营查看会员 360° 视图

1. 运营人员在会员列表按昵称、手机号或状态定位会员。
2. 打开会员详情，查看资料、有效等级、累计实付和订单统计。
3. 在最近订单中了解该会员近期消费情况。
4. 根据运营需要更新标签或备注。

## 6. 业务规则与状态

### 6.1 会员状态

| 状态 | 含义                             | 产品行为                 |
| ---- | -------------------------------- | ------------------------ |
| 正常 | 可正常作为会员登录和使用业务能力 | 登录后可访问本人业务数据 |
| 禁用 | 账号不可继续作为有效会员登录     | 已有历史订单等记录仍保留 |

当前会员管理页支持查看和筛选状态，不提供状态变更操作。

### 6.2 资料规则

- 昵称最长 64 个字符，头像使用可访问的图片地址。
- 性别仅支持保密、男、女三种值。
- 运营标签和备注各最长 255 个字符。
- 会员只能修改本人资料；运营标签与备注只允许有对应权限的后台人员维护。
- 微信身份、积分、累计实付和等级不能通过资料编辑直接修改。

### 6.3 360° 统计口径

- 订单总数包含会员全部未删除订单。
- 有效支付金额只统计待核销、已核销和已完成订单，不统计待付款、已取消和已退款订单。
- 平均有效实付为有效支付金额除以有效支付订单数；没有有效支付订单时显示 0。
- 当前等级按仍然启用且满足累计实付门槛的有效等级解析，无法解析时展示“普通会员”。

## 7. 权限与数据可见范围

- C 端会员只能查看和修改本人资料，不能指定其他会员身份。
- B 端查看会员与修改标签、备注使用不同权限控制。
- B 端内部备注不向 C 端展示。
- 会员与后台系统用户是两套身份，不能相互替代。

## 8. 异常与边界场景

| 场景                 | 处理                         |
| -------------------- | ---------------------------- |
| 查询不存在的会员     | 提示“会员不存在”             |
| 禁用会员尝试登录     | 登录失败，不发放有效会员会话 |
| 昵称、头像或备注超长 | 拒绝保存并提示输入不符合要求 |
| 性别值不在允许范围   | 拒绝保存                     |
| 会员没有订单         | 统计值显示 0，最近订单为空   |
| 默认等级不存在       | 仍可创建会员，等级暂为空     |

## 9. 模块联动

- 认证模块负责创建或识别会员、绑定手机号和校验账号状态。
- [订单模块](./04-order.md)提供 360° 视图中的消费统计和最近订单。
- [营销模块](./06-marketing.md)维护会员等级、积分余额和累计实付升级规则。
- [预约模块](./07-appointment.md)、[拼团模块](./09-group-buy.md)和[分销模块](./10-distribution.md)均以会员作为业务主体。

## 11. 验收标准

- **Given** 新微信用户首次成功登录，**When** 系统未找到对应会员，**Then** 创建正常状态会员并记录最后登录时间。
- **Given** 正常会员已登录，**When** 修改昵称、头像或性别，**Then** 仅更新本人允许编辑的资料。
- **Given** 运营人员拥有会员查看权限，**When** 按昵称或手机号搜索，**Then** 返回匹配会员且可查看 360° 视图。
- **Given** 会员存在已付款、已完成、取消和退款订单，**When** 查看消费统计，**Then** 有效实付只包含未退款的有效支付订单。
- **Given** 运营人员没有会员修改权限，**When** 尝试保存标签或备注，**Then** 操作被拒绝。
