# 预约时段容量设计

## 1. 目标与范围

当前预约仅限制同一会员不能重复提交同一天、同一时间。本次增加按“预约日期 + 时间段”计算的全局容量：每个时间段允许预约的客户上限可在管理端配置，默认 `1`。

本次交付：

- 服务端保存和读取统一的时段容量配置。
- 服务端仅接受每天 `10:00` 至 `18:00` 的 9 个整点时间段。
- 服务端返回指定日期各时间段的容量与满额状态。
- 服务端在并发提交时保证预约数不会超过配置上限。
- 管理端预约页面可查看和修改统一容量。
- 记录小程序后续需要完成的接口接入和满额置灰交互。

本次不修改小程序代码，不引入医生、门店、项目、排班、取消或改期。

## 2. 业务规则

- 可预约时间固定为 `10:00`、`11:00`、`12:00`、`13:00`、`14:00`、`15:00`、`16:00`、`17:00`、`18:00`。
- 容量配置对所有日期和时间段统一生效，默认值为 `1`，只允许正整数。
- 容量统计维度为“预约日期 + 预约时间”，不同会员也占用同一容量。
- 同一会员仍不能重复提交相同日期和时间。
- 达到容量后，任何会员再次提交该时间段都返回明确的“该时间段已约满”业务错误。
- 配置调低后不删除已有预约；若已有数量大于或等于新上限，该时间段立即视为已满。
- 过去的日期和时间仍不可预约。

## 3. 数据模型

新增单行表 `appointment_config`，字段为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint | 固定为 1 的配置记录主键 |
| `slot_capacity` | int | 每个时间段最多预约人数，默认 1 |
| 通用审计字段 | 与现有业务表一致 | 创建人、更新时间、逻辑删除等 |

阶段 6 增量 SQL 负责建表并写入主键为 `1`、容量为 `1` 的默认配置。服务读取时若该记录不存在，也按同样的固定主键和默认值补齐，兼容未及时初始化配置数据的环境。

继续保留现有 `appointment` 表的会员时间唯一索引，数据库兜底阻止同一会员的并发重复提交。

## 4. 服务端接口

### 4.1 管理端容量配置

- `GET /api/v1/appointments/config`：返回 `{ slotCapacity }`，需要预约查询权限。
- `PUT /api/v1/appointments/config`：接收 `{ slotCapacity }`，需要新增的预约配置权限；只允许大于等于 1 的整数。

### 4.2 C 端时段可用性

- `GET /api/v1/app/appointments/slots?appointmentDate=YYYY-MM-DD`
- 需要会员登录。
- 返回固定 9 个时间段，每项包含：
  - `time`
  - `bookedCount`
  - `capacity`
  - `remainingCount`
  - `full`
  - `available`
- `full` 只表示已约数达到容量；`available` 同时考虑是否满额和是否已过预约时间，客户端无需自行比较服务器时间。

### 4.3 创建预约

保留 `POST /api/v1/app/appointments` 的请求结构。新增两项校验：时间必须是固定 9 个时间段之一，并且该日期与时间的有效预约数必须小于当前容量。

创建过程在数据库事务中锁定唯一的预约配置行，然后统计目标时间段并写入预约。这个全局锁会串行化预约创建，但当前预约量低，换来最少代码和可靠的并发上限；若将来预约写入吞吐成为瓶颈，再升级为按日期和时间段锁定的号源表。

## 5. 管理端页面

在现有“预约管理”页面顶部增加“每时段预约上限”数字输入和保存按钮：

- 页面加载时读取当前配置。
- 输入最小值为 `1`，保存成功后重新读取配置。
- 保存按钮受预约配置权限控制。
- 预约列表和日历现有功能保持不变。

菜单 SQL 增加预约配置按钮权限并授权 ROOT、ADMIN。

## 6. 小程序后续改动记录

本次不修改 `yueji-web`。后续接入预约页时需要：

1. 增加预约 API 类型与调用：读取指定日期时段、提交预约。
2. 将预约 Tab 页接成日期选择、9 个整点时间按钮和提交按钮。
3. 时间段使用接口返回的 `available` 控制禁用和置灰，用 `full` 区分满额提示，不在前端自行统计容量。
4. 日期变化或提交成功后重新读取时段状态。
5. 即使按钮未及时刷新，也展示服务端返回的满额错误，服务端是容量校验的最终依据。

## 7. 错误与并发处理

- 非固定时间段：返回“请选择有效预约时间段”。
- 过去时间：沿用现有“预约时间不能早于当前时间”。
- 同一会员重复：沿用现有重复预约错误。
- 时间段满额：返回“该时间段已约满，请选择其他时间”。
- 并发请求：配置行写锁保证统计和插入串行执行，不能超过配置上限。

## 8. 验证

服务端最小测试覆盖：

- 默认容量为 1。
- 拒绝非固定整点时间。
- 不同会员提交同一日期和时间时，容量为 1 只允许第一条成功。
- 容量大于 1 时允许写入至上限，下一条被拒绝。
- 时段接口正确返回 9 项及满额、剩余数量。
- 配置更新拒绝 0、负数和非整数。

管理端执行类型检查和生产构建；服务端执行预约测试和生产构建。

## 9. 完成标准

- 默认配置下，同一天同一时间最多保存一位客户的预约。
- 管理员修改容量后，新容量立即用于时段查询和创建校验。
- 并发请求不能突破配置上限。
- 管理端可完成容量读取和保存。
- 小程序待办已在本设计和小程序改造计划中明确记录。
