# 阶段 8E 销售统计与分析设计

## 1. 目标与范围

阶段 8E 在现有订单和分销数据上提供实时销售分析，不新增统计汇总表：

- 管理端查看全系统已核销销售额、销售趋势、代理业绩排名和层级统计。
- 管理端查看单个代理的直属业绩汇总与趋势。
- 管理端按当前时间范围导出包含销售趋势、代理业绩和层级统计的 Excel。
- C 端提供代理本人直属业绩汇总与趋势接口，小程序页面继续暂缓。

本阶段不做奖励、原始订单明细、定时汇总、Redis 缓存、BI 自定义报表或小程序页面。

## 2. 固定统计口径

### 2.1 全系统销售

数据源为 `biz_order`：

- 只统计 `status = 3`、`is_deleted = 0` 且 `verify_time` 位于所选时间段内的已完成订单。
- 销售额为 `SUM(pay_amount)`，订单数为 `COUNT(id)`。
- 所有金额继续使用整数分传输，管理端显示和 Excel 导出时转换为元。

### 2.2 分销直属业绩

数据源为 `distribution_direct_sales`：

- 只统计 `status = 1`、`is_deleted = 0` 且 `applied_time` 位于所选时间段内的直属已核销业绩。
- 销售额为 `SUM(amount)`，订单数为 `COUNT(id)`，客户数为 `COUNT(DISTINCT buyer_member_id)`。
- 代理业绩只计算直属推荐客户，不计算二级团队业绩或佣金金额。

### 2.3 代理与层级归属

- 代理排名包含当前状态为已审核或已禁用、且未删除的代理；无业绩代理显示为 0。
- 默认按直属销售额降序，再按订单数降序、代理 ID 升序，保证分页顺序稳定。
- 层级统计按代理当前 `level_id` 归类；代理升级后，所选时间段的历史业绩随当前等级归类。
- 层级人数分别返回已审核人数、已禁用人数和合计人数。

## 3. 时间范围与趋势粒度

- 查询参数使用 `startDate`、`endDate`，格式为 `YYYY-MM-DD`。
- 两个参数都不传时默认上海时区当前自然月；只传一个参数时拒绝请求。
- 结束日期包含全天，SQL 使用 `[开始日 00:00:00, 结束日次日 00:00:00)` 半开区间。
- 开始日期不得晚于结束日期，查询跨度不得超过 5 年。
- 含首尾日期不超过 31 天时按日聚合，不超过 366 天时按月聚合，更长时按年聚合。
- 所选范围内没有数据的周期补 0，管理端图表不自行推导缺失周期。

## 4. 后端设计

### 4.1 组件

在现有 `distribution` 模块内增加 `DistributionAnalyticsService`，直接通过 `DataSource` 聚合现有表。继续复用现有 B/C 控制器、会员 JWT、管理员 RBAC、XLSX 依赖和统一响应结构。

增加一个纯规则文件负责：

- 上海时区日期范围归一化。
- 查询跨度校验。
- 日/月/年粒度选择。
- 趋势周期标签生成和数据库结果补零。

不增加实体、统计表、定时任务或缓存。

### 4.2 B 端接口

统一前缀 `/api/v1/distribution/analytics`：

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/overview` | `biz:distribution:analytics:list` | 汇总卡、双线趋势和层级统计 |
| GET | `/agents/page` | `biz:distribution:analytics:list` | 代理业绩排名分页，可按姓名/手机、当前等级筛选 |
| GET | `/agents/:agentId` | `biz:distribution:analytics:list` | 单个代理汇总与趋势 |
| GET | `/export` | `biz:distribution:analytics:export` | 按当前时间范围导出三工作表 Excel |

`overview` 返回：

- `summary.totalSalesAmount`：全系统已核销销售额。
- `summary.verifiedOrderCount`：全系统已核销订单数。
- `summary.distributionSalesAmount`：分销直属已核销销售额。
- `summary.performingAgentCount`：所选时间段产生直属业绩的代理数。
- `granularity`：`DAY`、`MONTH` 或 `YEAR`。
- `trend[]`：周期、全系统销售额、全系统订单数、分销直属销售额。
- `levels[]`：当前等级、代理人数拆分、直属销售额、订单数和客户数。

代理排名行返回代理 ID、姓名、手机、当前等级、账号状态、直属销售额、订单数和客户数。单个代理详情返回相同汇总字段及该代理的补零趋势。

### 4.3 C 端接口

`GET /api/v1/app/distribution/analytics/overview`：

- 使用会员 JWT 找到本人代理账号，不接受客户端传入代理 ID。
- 已审核和已禁用代理都可查看本人历史数据；其他会员返回业务错误。
- 返回本人直属销售额、订单数、客户数、自动粒度及补零趋势。
- 不返回客户身份、订单号、其他代理或层级统计。

### 4.4 Excel 导出

导出文件名为 `销售统计_<startDate>_<endDate>.xlsx`，包含：

1. `销售趋势`：周期、全系统销售额（元）、已核销订单数、分销直属销售额（元）。
2. `代理业绩`：排名、代理信息、当前等级、账号状态、直属销售额（元）、订单数、客户数；导出全部代理，不受页面分页影响。
3. `层级统计`：等级、已审核人数、已禁用人数、总人数、直属销售额（元）、订单数、客户数。

导出与页面调用相同服务方法，避免出现不同统计口径。

### 4.5 SQL 与权限

增加阶段 8E 增量 SQL：

- 为 `biz_order(status, verify_time)` 增加统计索引。
- 为 `distribution_direct_sales(status, applied_time)` 和 `(agent_id, status, applied_time)` 增加统计索引。
- 增加“销售统计”菜单及查看、导出权限，并授权 ROOT 和 ADMIN。

不改变历史订单或直属业绩数据。

## 5. 管理端设计

新增 `src/views/distribution/analytics/index.vue`，复用现有 Element Plus、ECharts 和下载工具：

1. 顶部日期范围筛选，默认当前月，提供查询、重置、导出按钮。
2. 四张汇总卡展示全系统已核销销售额、已核销订单数、分销直属销售额和产生业绩代理数。
3. 双折线趋势图展示全系统销售额与分销直属销售额，并标注当前自动粒度。
4. 层级统计表展示当前等级人数和所选时间段业绩。
5. 代理排名表支持姓名/手机号、当前等级筛选和分页；点击代理打开详情抽屉查看个人汇总与趋势。

页面金额以元显示，接口参数和响应金额仍为分。无数据时卡片显示 0，图表显示补零序列，表格显示空状态。

## 6. 错误处理与安全

- DTO 校验日期格式；服务层统一校验参数成对、日期顺序和 5 年上限。
- 查询不存在、已删除、待审核或已驳回的代理详情时返回业务错误。
- C 端代理 ID 只从会员 JWT 推导，防止越权查看其他代理业绩。
- 所有 SQL 使用绑定参数；代理关键字继续使用参数化模糊查询。
- 导出沿用管理员 RBAC 和 `skipResponseTransform`，不暴露原始订单与客户明细。

## 7. 测试与验收

### 7.1 自动检查

- 规则测试覆盖 31/32 天、366/367 天粒度边界、无数据补零和非法时间范围。
- 后端全量 Jest、ESLint 和生产构建通过。
- 管理端 ESLint、Prettier、Stylelint、类型检查和生产构建通过。

### 7.2 真实链路

使用现有测试数据和真实 HTTP 验证：

- 已支付未核销订单不进入任何销售统计，核销后进入总销售与直属业绩。
- 非分销会员订单只进入全系统销售，不进入代理业绩。
- 代理排名按销售额稳定排序，无业绩代理为 0。
- 层级统计按代理当前等级归类。
- C 端只返回本人汇总与趋势，不能指定或读取其他代理。
- Excel 包含三个工作表，日期范围、金额和页面一致。

## 8. 明确不做

- 不新增日/月/年汇总表、物化视图、后台统计任务或 Redis 缓存。
- 不统计待核销、退款或取消订单。
- 不按核销时等级快照归类，不计算二级团队业绩或佣金收益。
- 不提供原始订单、客户身份或消费明细导出。
- 不开发小程序页面；只交付代理本人 C 端统计接口。
