# 管理端品牌与菜单清理设计

## 目标

- 将管理端用户可见品牌和项目描述由 `vue3-element-admin` 改为「悦己」。
- 将 Apifox 菜单固定在顶级菜单末尾。
- 完整移除代码生成和平台文档模块。
- 修复商品管理菜单图标空白。

## 品牌范围

修改开发、生产环境标题、项目名称与描述、管理端说明文档中的项目标题。保留上游仓库 URL、技术出处和第三方源码注释中的 `vue3-element-admin`，避免破坏链接或抹去来源。没有新的品牌图片，因此继续使用现有 Logo。

## 菜单与前端

- Apifox 顶级目录排序设为 `999`，Mock 数据、初始化 SQL 和当前数据库保持一致。
- 删除代码生成页面、API、枚举、Mock 菜单和表单数据。
- 删除平台文档 Mock 菜单、表单数据及首页“文档”快捷入口。
- 保留 `iframe.vue`，因为 Apifox 仍使用它。
- 商品管理顶级菜单图标从不存在的 `goods.svg` 改为已注册的 `el-icon-Goods`。

## 服务端与数据库

- 删除 `CodegenModule`、控制器、服务、DTO 和模板。
- 删除初始化 SQL 中代码生成、平台文档菜单及角色授权，不再创建 `gen_table` 和 `gen_table_column`。
- 删除代码生成专用日志枚举、类型声明和依赖。
- 新增可重复执行的迁移 SQL：在事务中删除相关角色菜单与菜单树并更新 Apifox 排序和商品图标；事务提交后删除两张代码生成元数据表（MySQL DDL 会隐式提交）。
- 执行迁移前只读核对菜单与元数据数量；这些表不承载商品、订单、会员等业务数据。

## 影响

现有业务页面、接口和业务表不依赖代码生成模块，运行不受影响。删除后不能再通过后台可视化生成 CRUD；需要新页面时直接沿用现有业务页面模式开发。

## 验证

- 全仓搜索确认无代码生成、平台文档菜单和失效商品图标引用。
- 管理端运行类型检查和生产构建。
- 服务端运行生产构建。
- 数据库确认相关菜单、授权和元数据表已清除，Apifox 排序与商品图标已更新。
