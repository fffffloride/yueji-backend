# 移除 Apifox 与内嵌 iframe 能力设计

## 目标

彻底移除管理端的 Apifox 入口及通用内嵌 iframe 能力，保留普通外链在新标签页打开的现有能力。

## 范围

### 管理端

- 删除 `src/views/iframe.vue`。
- 从菜单管理表单删除“系统内嵌”打开方式、内嵌路由路径、缓存、路由名称提示及相关校验逻辑。
- 外链菜单只保留外链地址，统一在新标签页打开。
- 删除动态路由类型中仅供 iframe 使用的 `meta.externalUrl`。
- 删除 Mock 菜单、菜单树、权限树和菜单表单中的“接口文档/Apifox”数据。
- 删除中英文 README 中的 Apifox 接口文档链接。

### 服务端

- 删除菜单创建、更新和动态路由构建中对 `component = "iframe"` 的特殊处理。
- 外链菜单统一保存为无组件、无路由名称；动态路由路径直接使用外链地址，不启用缓存。
- 删除动态路由接口中仅供 iframe 使用的 `meta.externalUrl`。
- 保留菜单实体、DTO 和数据库中的 `externalUrl` 字段，继续支持普通外链。

### 数据库

- 从初始化 SQL 删除“接口文档”目录、Apifox 子菜单及其角色授权。
- 新增可重复执行的迁移 SQL，先删除相关角色菜单关系，再删除 Apifox 菜单及空的“接口文档”目录。
- 从既有菜单清理 SQL 删除调整 Apifox 排序的旧逻辑。

## 不在范围内

- 不用本地 Swagger 替换 Apifox 菜单。
- 不删除普通外链能力或 `external_url` 数据字段。
- 不改写过去已经提交的设计与计划文档；新设计作为后续状态依据。
- 不修改当前工作区中未提交的阶段 8E 销售统计代码。

## 验证

- 管理端执行类型检查和生产构建。
- 服务端执行类型检查或生产构建，并运行菜单相关测试（如现有测试可用）。
- 搜索运行时代码、Mock、README 和初始化/迁移 SQL，确认不再包含 Apifox URL、Apifox 菜单或 iframe 组件逻辑。
- 确认普通外链菜单仍由外链地址生成，并在新标签页打开。
