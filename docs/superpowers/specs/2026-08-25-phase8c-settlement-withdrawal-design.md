# 阶段 8C 结算与提现设计

## 1. 目标与范围

本阶段在 8B 佣金账本之上完成结算周期、结算单、提现申请、审核和人工打款确认，覆盖原始需求 4.8.5。

本批交付：

- 全系统统一的周、月、季、年结算规则。
- 产品销售分润结算单。
- 代理主动申请和系统自动生成提现申请两种模式。
- 两种模式统一经过人工审核和人工确认已打款。
- B 端配置、结算查询、提现审核接口和管理页面。
- C 端结算账户、提现申请和本人提现记录接口。
- 将订单退款规则恢复为仅已付款待核销订单可退款；核销完成后不可退款。

本批不交付：

- 真实微信商户打款；阶段 9 接入支付能力后替换人工确认。
- 小程序页面。
- 手续费、税费、部分退款。
- 任务奖励、总店奖励、其他分润类型和统计报表。
- 钱包余额缓存表或通用资金中台。

## 2. 已确认规则

- 提现模式由管理端页面切换，分为代理申请和系统自动生成申请。
- 无论哪种模式，提现都必须经过人工审核；审核通过后进入待打款，由管理员确认已打款。
- 全系统统一一个结算周期和结算日。
- 提现无最低门槛，金额只需大于 0 分。
- 上限按单笔提现金额限制。
- 申请模式允许代理自定义金额，但不得超过可提现余额和单笔上限。
- 自动模式每个结算日每位代理最多生成一笔，金额为可提现余额与单笔上限的较小值，剩余余额留到后续周期。
- 收款账户使用代理绑定会员的微信 OpenID，不允许代理或管理员手填替换。
- 核销后佣金才进入待结算；核销后的订单不能退款，因此不存在已打款佣金追偿或代理负余额。
- 配置变更只影响后续结算；历史结算单和提现单不重算、不编辑、不删除。

## 3. 总体方案

继续复用现有 `DistributionModule`，不新建只有单一实现的子模块。

采用“结算单 + 提现单、余额实时聚合”方案：

- 佣金账本仍是收益来源。
- 到期佣金生成不可变结算单。
- 提现单承担资金冻结、审核和打款状态。
- 账户余额从结算单和提现单聚合计算，不额外维护冗余余额字段。

当前数据量下，聚合查询比维护钱包余额与资金流水两套一致性更简单可靠。若单个代理的结算单和提现单达到明显影响查询的规模，再增加只读余额投影，不改变业务账本。

## 4. 数据模型

### 4.1 结算配置 `distribution_settlement_config`

全系统只保留一条有效配置：

- `cycle_type`：`WEEK`、`MONTH`、`QUARTER`、`YEAR`。
- `settlement_day`：周结时为星期 1～7；月结、季结、年结时为日期 1～28。
- `withdrawal_mode`：`APPLY` 代理申请、`AUTO` 系统自动生成申请。
- `single_limit_amount`：单笔提现上限，单位分，必须大于 0。
- 模板审计字段。

周结按配置星期处理上一个自然周；月结按配置日期处理上月；季结在新季度首月的配置日期处理上季度；年结在每年 1 月的配置日期处理上一年度。

### 4.2 佣金状态调整

`distribution_commission.status` 调整为：

- `0` 待核销：支付成功后生成，订单仍可退款。
- `1` 待结算：订单核销后进入，不可提现。
- `2` 已冲销：待核销订单退款后进入。
- `3` 已结算：已归入结算单，可计入可提现余额。

新增：

- 将现有 `available_time` 迁移并重命名为 `pending_settlement_time`，保存核销进入待结算的时间。
- `settlement_id`：所属结算单，可空。
- `settled_time`：结算时间，可空。

已结算佣金不得再次结算；唯一关联和事务锁保证重复任务不重复入账。

### 4.3 结算单 `distribution_settlement`

- `settlement_no`：唯一结算单号。
- `agent_id`：受益代理。
- `profit_point`：本阶段固定为 `PRODUCT_SALES`。
- `period_start`、`period_end`：完整自然周期边界。
- `commission_count`：包含的佣金条数。
- `amount`：结算金额，单位分。
- `settled_time`：生成时间。
- 模板审计字段。

唯一键为 `(agent_id, profit_point, period_start, period_end)`。同一周期无待结算佣金时不生成零金额结算单。

### 4.4 提现单 `distribution_withdrawal`

- `withdrawal_no`：唯一提现单号。
- `agent_id`、`member_id`：代理和绑定会员快照。
- `source_mode`：`APPLY` 或 `AUTO`。
- `amount`：提现金额，单位分。
- `openid_snapshot`：创建提现单时的微信 OpenID。
- `status`：`0` 待审核、`1` 待打款、`2` 已驳回、`3` 已打款。
- `review_by`、`review_time`、`review_reason`：审核信息。
- `transfer_no`、`paid_by`、`paid_time`、`paid_remark`：人工打款确认信息。
- `auto_period_end`：自动生成时记录触发结算周期结束日；主动申请为空。
- 模板审计字段。

自动申请唯一键为 `(agent_id, source_mode, auto_period_end)`，确保同一结算日只生成一笔。提现单只允许状态向前推进，不提供编辑或删除接口。

## 5. 余额口径

结算账户按代理实时聚合：

- 待结算金额：状态为待结算的佣金金额之和。
- 已结算总额：全部结算单金额之和。
- 冻结金额：待审核和待打款提现单金额之和。
- 已提现金额：已打款提现单金额之和。
- 可提现余额：已结算总额减去待审核、待打款和已打款提现单金额。

已驳回提现不占用余额。所有余额查询过滤软删除数据，并使用整数分计算。

## 6. 业务流程

### 6.1 支付、核销与退款

1. 支付成功按 8B 规则生成待核销佣金。
2. 已付款待核销订单可整单退款；退款将待核销佣金改为已冲销。
3. 核销将佣金改为待结算，同时完成订单。
4. 已核销或已完成订单不可退款。
5. 撤销 8B 为完成订单退款新增的状态流转、支付放行和会员权益回退逻辑；保留待核销退款原有库存、销量、券和积分返还。

### 6.2 周期结算

定时任务定期检查配置是否到达结算日。到期后计算上一完整周期，按代理查询 `pending_settlement_time` 落在该周期内、状态为待结算且未关联结算单的佣金：

1. 锁定候选佣金。
2. 按代理汇总数量和金额。
3. 创建结算单。
4. 将佣金关联结算单并改为已结算。
5. 完成全部结算后，自动模式扫描所有仍有可提现余额的已通过或已禁用代理并尝试生成申请；即使本期没有新增佣金，上期超过单笔上限的余额也可在本期继续生成一笔。

管理端可手动触发一次“执行已到期结算”，与定时任务调用同一服务方法。未到结算日时不提前结算；重复执行由唯一键和状态条件直接返回已有结果。

### 6.3 主动申请提现

只有已通过或已禁用代理可以提取历史已结算佣金；待审核、已驳回代理不可申请。

事务内锁定代理后重新计算余额，校验：

- 当前模式为 `APPLY`。
- 金额为整数分且大于 0。
- 金额不超过单笔上限。
- 金额不超过可提现余额。
- 绑定会员存在非空微信 OpenID。

校验通过后创建待审核提现单，余额立即进入冻结口径。

### 6.4 自动生成提现申请

只有配置模式为 `AUTO` 时执行。周期结算完成后，对每个有可提现余额的已通过或已禁用代理：

- 重新计算可提现余额。
- 取 `min(可提现余额, 单笔上限)`。
- 金额大于 0 且存在微信 OpenID时创建待审核提现单。
- 每个代理每个结算周期最多一笔；剩余余额不拆单，留到后续周期。

自动模式也必须审核，不会自动标记打款成功。

### 6.5 审核和确认打款

- 待审核提现可审核通过或驳回。
- 审核通过后状态直接进入待打款，审核理由必填。
- 驳回后状态进入已驳回，驳回理由必填，冻结金额立即释放。
- 待打款提现可确认已打款；转账流水号必填，状态进入已打款。
- 重复请求返回当前结果，不重复改变余额口径。
- 已驳回和已打款均为终态。

## 7. 接口设计

### 7.1 C 端

- `GET /api/v1/app/distribution/settlement/account`：本人结算配置摘要、下一结算日、待结算、可提现、冻结、累计已提现金额。
- `POST /api/v1/app/distribution/withdrawals`：提交自定义金额提现申请，仅申请模式可用。
- `GET /api/v1/app/distribution/withdrawals/page`：本人提现记录分页。

接口使用现有会员 JWT，不接受客户端提交代理 ID、会员 ID、OpenID 或余额字段。

### 7.2 B 端

- `GET /api/v1/distribution/settlement/config`：查询全局配置。
- `PUT /api/v1/distribution/settlement/config`：更新全局配置。
- `POST /api/v1/distribution/settlements/run-due`：手动执行已到期结算。
- `GET /api/v1/distribution/settlements/page`：按代理、分润类型和周期查询结算单。
- `GET /api/v1/distribution/withdrawals/page`：按代理、来源模式、状态和时间查询提现单。
- `PUT /api/v1/distribution/withdrawals/:id/audit`：审核通过或驳回。
- `PUT /api/v1/distribution/withdrawals/:id/paid`：确认已打款。

新增权限点覆盖配置查询/修改、结算查询/执行、提现查询/审核/打款。

## 8. 管理端页面

新增 `src/views/distribution/settlement/index.vue`，一个页面包含三个页签：

- 结算设置：周期、结算日、提现模式、单笔上限；根据周期动态显示星期或日期输入。
- 结算记录：代理、分润类型、周期筛选，展示结算单号、佣金数量和金额。
- 提现审核：代理、来源模式、状态、时间筛选；提供审核、驳回和确认已打款操作。

金额页面使用元，提交时转为整数分。结算记录和终态提现单只读。

## 9. 并发、幂等与失败处理

- 结算按佣金状态和 `settlement_id` 选取，事务内加锁并使用周期唯一键。
- 提现创建锁定代理记录后重新聚合余额，防止并发超额申请。
- 自动提现使用周期唯一键，定时任务和人工补偿并发时只生成一次。
- 审核和打款使用状态条件推进；重复请求返回当前状态。
- 单个代理结算失败记录日志，不阻断其他代理，下次任务继续重试。
- 结算和提现数据不物理删除，不提供金额修改入口。
- 当前余额使用聚合查询；单代理账目数量明显影响响应时再增加余额投影。

## 10. 测试与验收

最小规则测试：

- 周、月、季、年上一完整周期及下一结算日计算。
- 提现金额、单笔上限和状态流转。

最小资金闭环测试：

1. 支付生成待核销佣金，重复支付不重复。
2. 待核销退款转已冲销。
3. 核销转待结算，完成订单退款被拒绝。
4. 到期结算生成唯一结算单，佣金只结算一次。
5. 主动申请冻结余额，超额申请失败，驳回后额度恢复。
6. 自动模式每个代理每期只生成一笔且金额不超过上限。
7. 两种模式都必须审核；确认打款后累计已提现正确。

交付验收：

- 后端全量 Jest 和生产构建通过，改动文件 ESLint 通过。
- 管理端类型检查、生产构建和改动页面 ESLint/Stylelint 通过。
- 数据库迁移、菜单权限和 UTF-8 中文名称在本地 MySQL 验证。
- 真实 HTTP 完成“核销 → 待结算 → 周期结算 → 申请/自动生成 → 审核 → 确认打款”闭环。
- 后端和管理端保持运行，未执行会清空业务数据的全量种子脚本。

## 11. 完成标准

运营人员能在页面切换申请/自动模式、配置周期和单笔上限，查询结算单，审核提现并确认人工打款；代理能查询结算账户、主动申请和查看记录；核销佣金只能在完整周期到期后进入可提现余额，所有结算、申请、审核和打款操作可重试且不重复记账；核销后的订单明确不可退款。
