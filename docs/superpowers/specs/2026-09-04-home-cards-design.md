# 首页卡片配置

按用户确认的独立入口实施：页面管理 → 首页卡片（`/decoration/cards`）。品牌背书仍管理原来的「悦己严选」区块。

- 独立表 `decoration_home_cards` 的单行 JSON 数组保存 0–10 张卡片，整体原子保存，数组顺序即展示顺序。
- 每张卡片仅有 `title`（100 字）、`imageUrl`（500 字 HTTP/HTTPS 图片地址）、`content`（200000 字富文本）。
- 管理端复用图片上传和 WangEditor，使用表格列表和右侧新增/编辑抽屉，支持位置调整与删除；各操作即时保存，取消不改变原数据；使用独立查询/编辑权限。
- `GET/PUT /api/v1/decoration/cards` 读写配置；公开首页聚合接口新增 `cards`，为空时返回空数组。
- 首页替换原写死卡片，仅展示背景图，保持现有 272rpx 高度和圆角；点击打开右侧全屏抽屉，固定标题、关闭按钮、可滚动富文本和安全区。图片失败保留占位并仍可打开内容。
- 服务端验证数组上限、嵌套必填字段与 URL；整组保存避免并发新增超过上限；保存失败保留编辑内容。
- 验收覆盖 0/10/11 张、非法字段、持久化与排序、菜单权限、首页开关抽屉和长内容；检查三端编译和小程序构建。

## 本地验收与部署

- 本地执行 `sql/mysql/home_cards.sql` 创建独立表与菜单；已有数据不会被覆盖。生产部署也须先执行此脚本。
- SQL 菜单变更后，使 Redis 哈希 `system:role:perms` 中 ADMIN/ROOT 角色缓存失效，再刷新管理端页面以重新加载权限。
- 本地通过 DTO/服务测试、后端构建、管理端类型与定向 lint、小程序 `verify:ui`。
- 初版用 10 张临时验收卡片验证后台上限、编辑标题、调整顺序、保存；H5 在 375×812 与 430×932 下验证纯图片、独立抽屉标题与长内容滚动。初版验收数据已清理，后续用户录入的内容保留。
- 微信开发者工具和真机交互仍需发布前人工验收。

## 首页活动卡片与后台交互统一（追加）

- 新增独立页面管理路由 `/decoration/promo-cards`，字段 `title`、`imageUrl`、`linkUrl`，最多 4 张；单行 JSON 表 `decoration_promo_cards` 原子保存。
- `GET/PUT /api/v1/decoration/promo-cards` 使用独立查询/编辑权限；首页聚合接口返回 `promoCards`。首页保留两列宫格，只展示背景图，按配置顺序跳转。
- 地址只接受 `/pages/`、`/pages-sub/` 开头的站内页面路径和 HTTP/HTTPS 完整地址；站内页复用统一导航，完整地址复用现有 web-view。微信端外链依赖业务域名配置。
- 两个后台路由共用现有表格、图片上传、富文本、位置排序控件及右侧编辑抽屉；编辑使用副本，保存成功后才更新列表，失败保留输入；新增按钮受数量上限和权限约束。
- 既有数据库先执行 `sql/mysql/promo_cards.sql`，再使管理员角色权限缓存失效并完整刷新后台；既有首页卡片数据保持原样。
