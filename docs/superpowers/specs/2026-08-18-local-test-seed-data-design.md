# 本地测试环境业务种子数据设计

## 目标

为本地 Docker MySQL 提供一套可重复执行的业务种子数据，覆盖阶段 1–5 已实现模块的正常、边界和历史状态，支持后台分页、筛选、详情和小程序联调。

当前整个系统均处于测试阶段，因此数据使用自然业务名称，不添加“测试”前缀。

## 重置边界

只清空并重建以下业务表：

- `member`
- `member_level`
- `member_points_log`
- `product_category`
- `product`
- `product_sku`
- `cart`
- `biz_order`
- `biz_order_item`
- `biz_payment`
- `biz_refund`
- `coupon`
- `coupon_scope`
- `member_coupon`

保留所有 `sys_*` 表，包括后台账号、角色、菜单、权限、字典和系统配置。

## 实现形式

新增单个 `sql/mysql/biz_test_seed.sql` 文件，由 MySQL 8 原生 SQL 完成重置和造数，不增加脚本框架或依赖。

脚本使用 `DELETE + INSERT` 并包裹在事务中。任何插入或校验失败都回滚到执行前状态，不使用会自动提交且无法回滚的 `TRUNCATE`。数据使用稳定的显式主键和业务编号，以便跨表关联并方便排查。

## 数据规模与场景

### 会员与等级

- 4 个等级：普通、白银、黄金、黑钻，包含不同消费门槛和折扣率。
- 60 个会员，覆盖不同等级、积分余额、累计消费、注册时间、最后登录时间、标签、备注和性别。
- 包含正常会员、禁用会员、无手机号会员及长期未登录会员。

### 商品与库存

- 三级分类结构，覆盖皮肤管理、注射美容、光电项目和身体护理等业务方向。
- 约 36 个商品、70 个以上 SKU，支持列表分页和分类筛选。
- 覆盖上架、下架、售罄、低库存、多规格、禁用 SKU 和逻辑删除历史 SKU。
- 商品聚合库存与有效 SKU 库存保持一致；图片使用固定种子的公开占位图地址。

### 购物车

- 覆盖选中、未选中、单件、多件、多商品和多会员购物车。
- 保留少量库存变化后的遗留购物车项，用于校验结算时的二次校验。

### 订单、支付与退款

- 约 120 个订单，创建时间分布在近 90 天，覆盖分页、日期筛选和会员 360 统计。
- 六种订单状态均有数据：待付款、待核销、已核销、已完成、已取消、已退款。
- 订单金额、优惠拆分、积分抵扣、支付金额和商品明细保持算术一致。
- 支付覆盖待支付、成功、失败和已退款；退款覆盖处理中、成功和失败。
- 已支付订单具有支付时间；已核销和已完成订单具有核销信息；取消和退款订单具有对应原因与流水。

### 积分与优惠券

- 积分流水覆盖初始化、订单抵扣、取消返还、退款返还和订单完成赠送，并与会员余额保持一致。
- 12 个优惠券模板，覆盖满减、折扣和兑换三种类型，以及全场、分类和商品范围。
- 模板覆盖草稿、启用、停用、未开始、领取中、已结束和库存领完场景。
- 会员券覆盖未使用、锁定、已使用和过期；锁定或已使用券与对应订单关联。

## 可重复执行与安全

- 每次执行都会重建全部业务数据，适合数据被频繁手工修改后的快速恢复。
- 执行前确认目标库为本地 Docker 的 `youlai_admin`。
- 脚本开头校验当前数据库名；结尾执行数量、状态分布和关键关联校验。
- 不删除 Docker 数据卷，不修改系统表，不创建后台账号。

## 验收标准

- 14 张业务表均成功重建数据。
- 会员、商品和订单数量达到上述规模，所有核心状态均有样本。
- 订单明细、支付、退款、积分、优惠券不存在孤立关联。
- 商品汇总库存等于有效 SKU 库存之和。
- 订单金额满足 `pay_amount = total_amount - member_discount - coupon_amount - points_deduct`，且 `discount_amount` 等于三类优惠之和。
- 脚本连续执行两次均成功，第二次结果数量与第一次一致。
- 后端测试和构建继续通过。

## 明确不做

- 不生成 `sys_*` 系统数据。
- 不上传或维护 MinIO 图片文件。
- 不通过业务 API 模拟逐次操作。
- 不模拟生产级百万数据、并发写入或性能压测；需要性能验证时另建专用数据集。
