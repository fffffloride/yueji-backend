# 阶段 8A + 8B 分销身份与佣金账本设计

## 1. 重新评估与本批范围

完整的 4.8 分销需求拆为五批：

- 8A：代理类型、分销等级、代理商、审核、团队关系。
- 8B：一级/二级佣金、订单事件、佣金账本、自动升级。
- 8C：结算周期、提现申请、限额与打款；真实微信自动打款延后到支付能力具备后。
- 8D：任务、总店奖励、奖励发放。
- 8E：销售统计、排名、趋势和导出。

本批交付 8A + 8B 的最小收益闭环：服务端、管理端，以及供小程序后续接入的 C 端接口。本批不修改 `yueji-web` 页面。

明确不做：

- 结算单、提现、微信打款、任务、总店奖励、销售统计和导出。
- 按商品、SKU、品类或活动单独配置佣金。
- 部分退款佣金拆分；沿用当前整单退款能力。
- 新消息队列、通用规则引擎或通用工作流。

## 2. 已确认的业务规则

- 推荐关系采用首次邀请绑定；产生佣金后永久冻结，不允许换绑。
- 支付成功按订单实付金额生成待结算佣金。
- 订单核销后佣金变为可提现，并计入直属有效销售额。
- 整单退款后佣金自动冲销，直属有效销售额扣回。
- 自动升级只看直属推荐会员的已核销实付累计；达到门槛后只升不自动降。
- 管理员可手动升降级和设置代理专属佣金比例，必须填写原因并记录审计日志。
- 等级配置全局一级、二级比例和允许分销深度；商品级比例以后再做。
- 佣金使用支付时的关系、等级和比例快照，配置变更不追溯历史订单。
- 金额使用整数分，比例使用万分比；例如 `1200` 表示 `12%`。

## 3. 模块与复用边界

新增一个 `DistributionModule`，内部直接包含身份配置、代理商、推荐关系、团队查询和佣金账本，不再拆出只有单一实现的子模块。

复用现有能力：

- `MemberModule`：会员身份与本人 C 端鉴权。
- `OrderModule`：订单实付金额、支付、核销、退款状态和领域事件。
- `DomainEvents`：订阅 `order.paid`、`order.verified`、`order.refunded`。
- 现有 TypeORM、RBAC、分页、审计字段、定时任务和管理端表格模式。

不修改 `biz_order` 保存分销字段；订单与受益人、比例、金额的快照全部保存在佣金账本。

现有领域事件是进程内异步通知，因此采用“事件实时处理 + 每分钟按订单最终状态补偿”的现有拼团模式。两条路径调用同一幂等同步方法，不引入消息队列。

## 4. 数据模型

表统一使用 `utf8mb4` 和现有审计字段。

### 4.1 代理类型 `distribution_agent_type`

- `name`：自定义名称，如个人、机构。
- `status`：`0` 停用、`1` 启用。
- `sort`：升序排序。

已被代理使用的类型不得删除；停用后不可用于新增或修改，不影响历史代理。

### 4.2 分销等级 `distribution_level`

- `name`：自定义名称，如总店、合伙人、荣誉股东。
- `rank`：等级顺序，值越大等级越高，唯一。
- `upgrade_sales_amount`：自动升级所需直属已核销实付累计，单位分。
- `distribution_depth`：`1` 或 `2`。
- `level1_rate_bps`、`level2_rate_bps`：一级、二级佣金万分比。
- `status`：`0` 停用、`1` 启用。
- `sort`：展示顺序。

比例必须在 `0～10000`；深度为 1 时二级比例必须为 0。已被代理或佣金快照引用的等级不得删除。配置修改只影响之后支付的订单。

### 4.3 代理商 `distribution_agent`

- `member_id`：对应会员，唯一。
- `real_name`、`mobile`、`wechat`、`contact_remark`：基础联系方式。
- `type_id`、`level_id`。
- `parent_agent_id`：上级代理，可空，形成团队树。
- `invite_code`：系统生成的唯一邀请码。
- `custom_level1_rate_bps`、`custom_level2_rate_bps`：可空；非空时覆盖等级比例。
- `direct_verified_sales`：直属推荐会员当前有效的已核销实付累计，单位分。
- `status`：`0` 待审核、`1` 已通过、`2` 已驳回、`3` 已禁用。
- `apply_time`、`audit_time`、`audit_by`、`audit_remark`。

C 端申请和后台新增都写入此表，不再增加单独申请表。后台新增可直接选择会员、类型、等级和上级；C 端申请进入待审核。

审核通过时：若会员已有推荐关系，则将该推荐代理设为 `parent_agent_id`；后台也可显式选择上级。任何上级调整都必须校验不能指向自己或自己的下级。

### 4.4 推荐关系 `distribution_referral`

- `member_id`：被推荐会员，唯一。
- `referrer_agent_id`：首次绑定的直属推荐代理。
- `bound_time`。
- `frozen_time`：首次产生佣金时写入；非空后永久禁止换绑。

绑定时要求推荐代理已审核通过且启用，禁止自绑、重复绑定和形成代理团队环。普通会员首次绑定后默认不提供换绑接口；后台仅能在 `frozen_time` 为空时更正，并记录原因。

### 4.5 佣金账本 `distribution_commission`

- `order_id`、`order_no`、`buyer_member_id`。
- `beneficiary_agent_id`：受益代理。
- `source_agent_id`：本单一级推荐代理，用于还原链路。
- `depth`：`1` 或 `2`。
- `base_amount`：订单实付金额快照。
- `rate_bps`：实际使用比例快照。
- `commission_amount`：`floor(base_amount * rate_bps / 10000)`。
- `agent_level_id`、`agent_level_name`：受益代理等级快照。
- `status`：`0` 待结算、`1` 可提现、`2` 已冲销。
- `paid_time`、`available_time`、`reversed_time`。

唯一索引 `(order_id, beneficiary_agent_id, depth)` 防止重复记账。账本只允许状态推进，不允许人工修改金额或删除。

### 4.6 代理操作日志 `distribution_agent_log`

- `agent_id`。
- `action`：审核通过、驳回、启用、禁用、手动调级、比例调整、关系更正。
- `before_value`、`after_value`：JSON 快照。
- `reason`、`operator_id`、`created_at`。

日志只新增，不编辑、不删除。

### 4.7 直属业绩账本 `distribution_direct_sales`

- `order_id`：订单唯一。
- `buyer_member_id`、`agent_id`、`referral_id`：支付时的直属关系快照。
- `amount`：订单实付金额快照。
- `status`：`0` 待核销、`1` 已计入、`2` 已冲销。
- `paid_time`、`applied_time`、`reversed_time`。

该表独立于佣金比例：即使直属代理一级比例为 0，只要支付时身份有效，核销后仍能累计升级业绩。唯一订单约束和状态条件更新保证业绩只增减一次。

## 5. 核心流程

### 5.1 申请、审核与绑定

1. 会员提交代理申请；已有待审核或已通过代理身份时拒绝重复申请。
2. 管理员审核通过时指定类型和等级，可保留推荐关系形成的上级；驳回必须填写原因。
3. 普通会员提交邀请码进行首次绑定；校验邀请码、代理状态、自绑和团队成环。
4. 代理被禁用后保留身份、关系和历史账本，但新订单不再给该代理生成佣金。

### 5.2 支付生成佣金

收到 `order.paid` 后执行：

1. 读取买家唯一推荐关系，得到一级推荐代理。
2. 一级代理在支付时已通过且启用，才生成一级佣金。
3. 读取一级代理的 `parent_agent_id`；该上级代理已通过、启用且其自身等级允许二级分销时，才按上级的二级比例生成二级佣金。
4. 每位受益代理的有效比例优先取个人专属比例，否则取当前等级比例。
5. 为有效直属代理创建待核销直属业绩账本；再使用订单 `pay_amount` 计算佣金，保存关系、等级、比例和金额快照，状态为待结算。
6. 写入推荐关系 `frozen_time`。唯一索引保证重复支付事件无副作用。

只有佣金金额大于 0 的代理才写佣金账本；待审核、驳回、禁用、超出分销深度或比例为 0 的层级跳过佣金。直属业绩账本不受佣金比例是否为 0 影响。

### 5.3 核销、业绩与自动升级

收到 `order.verified` 后：

- 将该订单待结算佣金改为可提现，重复事件不重复更新。
- 将待核销直属业绩账本改为已计入，并给快照中的直属推荐代理增加一次 `pay_amount` 直属有效销售额。
- 从所有启用等级中选择门槛不高于当前销售额的最高等级；仅在其 `rank` 高于当前等级时自动升级。
- 自动升级写操作日志。以后发生退款时扣回销售额，但不自动降级。

等级门槛示例：荣誉股东配置 `upgrade_sales_amount = 10000000`，即直属有效销售额达到 10 万元自动升级。

### 5.4 退款冲销

收到 `order.refunded` 后：

- 该订单所有待结算或可提现佣金改为已冲销，保留原金额和快照。
- 若直属业绩账本已计入，则将其改为已冲销，并从快照代理销售额扣回一次 `pay_amount`，最低为 0。
- 不因扣回自动降级；管理员可根据业务情况手动降级并填写原因。

当前核销会立即把订单推进到已完成，而现有退款仅允许“已付款待核销”订单。为满足已确认的“可提现后退款也冲销”，本批将整单退款扩展到已完成订单，并复用现有库存、销量、积分/权益回退；仍不支持部分退款。

### 5.5 事件补偿

每分钟分页检查需要同步的已付款、已完成和已退款订单：

- 已付款且无直属业绩账本：补建直属业绩快照和待结算佣金。
- 已完成且账本仍待结算：推进可提现并补记直属业绩。
- 已退款且账本未冲销：推进冲销并回退直属业绩。

佣金与直属业绩唯一索引、状态条件更新保证事件与补偿任务并发时仍只处理一次。单笔失败记录日志并在下轮重试，不阻断其他订单。

## 6. 接口设计

### 6.1 C 端

- `POST /api/v1/app/distribution/applications`：会员提交申请。
- `GET /api/v1/app/distribution/profile`：本人代理身份、邀请码、直属销售额及待结算/可提现/已冲销汇总。
- `POST /api/v1/app/distribution/referrals/bind`：使用邀请码首次绑定推荐代理。
- `GET /api/v1/app/distribution/commissions/page`：本人佣金明细分页。
- `GET /api/v1/app/distribution/team`：本人直属代理团队摘要；仅已通过且启用代理可访问。

所有本人接口从登录上下文取 `memberId`，不接收客户端传入的会员或代理 ID。

### 6.2 B 端

- `/api/v1/distribution/agent-types`：分页、表单详情、新增、编辑、启停、删除未使用类型。
- `/api/v1/distribution/levels`：分页、表单详情、新增、编辑、启停、删除未使用等级。
- `GET /api/v1/distribution/agents/page`、`GET /api/v1/distribution/agents/:id`：代理商分页和详情。
- `POST /api/v1/distribution/agents`、`PUT /api/v1/distribution/agents/:id`：新增和维护基础信息。
- `PUT /api/v1/distribution/agents/:id/audit`：审核通过或驳回。
- `PUT /api/v1/distribution/agents/:id/status`：启用或禁用。
- `PUT /api/v1/distribution/agents/:id/level`：手动升降级并填写原因。
- `PUT /api/v1/distribution/agents/:id/rates`：设置或清除专属一级、二级比例并填写原因。
- `GET /api/v1/distribution/team/tree`：按代理根节点查询团队树。
- `GET /api/v1/distribution/commissions/page`：佣金账本分页，只读。
- `GET /api/v1/distribution/agents/:id/logs`：操作日志分页，只读。

权限前缀使用 `biz:distribution:type:*`、`biz:distribution:level:*`、`biz:distribution:agent:*`、`biz:distribution:team:list` 和 `biz:distribution:commission:list`。

## 7. 管理端

新增“分销管理”菜单，授权 ROOT 与 ADMIN：

- `src/views/distribution/type/`：代理类型 CRUD、启停。
- `src/views/distribution/level/`：等级名称、门槛、深度、一级/二级比例、启停。
- `src/views/distribution/agent/`：筛选、新增、编辑、审核、启停、调级、专属比例和详情抽屉。
- `src/views/distribution/team/`：团队树；点击节点查看代理、直属业绩和佣金汇总。首批只读，结构调整统一从代理商页完成。
- `src/views/distribution/commission/`：按订单、代理、层级、状态和时间筛选佣金明细，只读。

沿用现有 API 分层、`usePageTable`、分页、表单校验和树组件；不新增前端依赖。SQL 显式使用 `utf8mb4`，避免中文菜单乱码。

## 8. 校验、权限与异常处理

- 类型、等级、代理、推荐关系和佣金查询都过滤软删除数据。
- 等级比例、代理专属比例必须在 `0～10000`；专属二级比例仅在代理等级分销深度为 2 时可用。
- 代理会员唯一、邀请码唯一、推荐会员唯一、佣金业务键唯一。
- 上级代理调整在事务内锁定目标代理并检查自指和后代环路。
- 有推荐关系、下级代理或佣金记录的代理不允许删除，只允许禁用；首批不提供代理物理删除接口。
- 待审核、已驳回和已禁用代理不能访问团队接口，也不能从新订单获佣。
- 佣金金额只由订单事件生成，管理端无修改和删除入口。
- 对外返回明确业务错误，不暴露数据库、支付驱动或内部堆栈。
- 退款、核销和补偿失败可重试；重复事件不重复佣金、业绩或升级日志。

## 10. 完成标准

运营人员能配置代理类型和等级，新增、审核、禁用、调级和设置专属比例；会员能通过 C 端接口申请代理并首次绑定推荐关系；订单支付、核销和整单退款能够幂等推进佣金待结算、可提现和已冲销状态；直属有效销售额达到门槛后自动升级；团队结构、操作日志和佣金明细在管理端可查询。
