# 阶段 8D 分销任务管理设计

## 1. 目标与范围

本阶段在现有代理、直属销售和订单核销数据之上完成销售任务发布与完成监控，覆盖原始需求 4.8.6 中已确认保留的部分。

本批交付：

- 后台创建、编辑、发布、取消和查询销售任务。
- 按全部代理、指定等级或指定代理生成固定任务名单。
- 按直属推荐客户的已核销销售额或已核销订单数实时判断完成状态。
- 后台查看任务总进度和每位代理的完成情况。
- C 端查询本人被分配的任务和实时进度接口。

本批不交付：

- 现金奖励、其他福利、奖励审核或奖励发放。
- 代理提交、人工完成审核、任务反馈或人工修改完成状态。
- 完成进度流水和精确首次完成时间。
- 销售统计导出、趋势图和业绩排名；这些内容留到阶段 8E。
- 小程序任务页面；本阶段只提供 C 端接口。

## 2. 已确认规则

- 每个任务只选择一种完成指标：已核销销售额或已核销订单数。
- 只统计代理直属推荐客户的订单，不统计二级或更深团队订单。
- 任务发布范围可选全部代理、指定等级或指定代理。
- 发布时生成代理名单快照；发布后新增、升级或降级的代理不自动加入或移出。
- 草稿可编辑；发布后任务内容、目标、周期和名单不可修改，只能取消。
- 任务不设置任何奖励，只显示进度和是否完成。
- 任务进度在列表或详情查询时从现有直属销售记录实时计算，不做后台累计，不保存首次完成时间。

## 3. 总体方案

继续复用现有 `DistributionModule`，不拆出只有单一实现的新模块。

只新增“任务”和“任务代理名单”两张表：

- 任务表保存任务规则、有效期、分配方式和发布状态。
- 名单表保存发布时确定的代理 ID，并用唯一键防止重复分配。
- 现有 `distribution_direct_sales` 是唯一进度来源；不新增进度表、贡献流水或定时任务。

查询任务时按任务、代理和核销时间对直属销售记录做分组聚合，得到销售额、订单数、完成比例和完成状态。该方案数据结构最少，重复查询天然幂等；如果未来单次查询量明显影响响应，再增加异步进度投影，不改变任务和名单模型。

## 4. 数据模型

### 4.1 任务 `distribution_task`

- `name`：任务名称，最多 100 字。
- `description`：任务描述和要求，最多 1000 字。
- `metric_type`：`SALES_AMOUNT` 已核销销售额、`ORDER_COUNT` 已核销订单数。
- `target_value`：目标值；销售额单位为分，订单数为正整数。
- `start_time`、`end_time`：任务有效期，开始时间必须早于结束时间。
- `assignment_scope`：`ALL`、`LEVEL`、`AGENT`。
- `target_level_id`：指定等级时保存等级 ID，其他范围为空。
- `target_agent_ids`：指定代理时保存去重后的代理 ID JSON 数组，其他范围为空；只用于草稿编辑和发布审计。
- `status`：`0` 草稿、`1` 已发布、`2` 已取消。
- `published_time`、`cancelled_time`：发布时间和取消时间，可空。
- 模板审计字段。

“未开始、进行中、已结束、已取消”是接口根据基础状态和当前时间返回的展示状态，不额外写入数据库。草稿允许软删除；已发布和已取消任务不提供删除接口。

### 4.2 任务名单 `distribution_task_assignee`

- `task_id`：任务 ID。
- `agent_id`：发布时命中的代理 ID。
- 模板审计字段。

唯一键为 `(task_id, agent_id)`。名单表不保存进度、完成状态或完成时间；代理姓名、等级等展示信息查询现有代理表。

## 5. 发布与生命周期

### 5.1 草稿

- 新增任务默认是草稿。
- 草稿可编辑任务内容、指标、周期和分配范围，也可软删除。
- 销售额目标按整数分保存；订单数目标必须是正整数。
- `LEVEL` 必须指定一个等级；`AGENT` 必须指定至少一个不重复代理 ID；其他范围字段必须为空。

### 5.2 发布

发布在一个事务内完成：

1. 锁定草稿任务并重新校验字段。
2. 若任务开始时间早于首次发布时间，将开始时间归一为发布时间，防止追溯计算历史销售；未来开始时间保持不变。
3. `ALL` 选择当前全部已审核代理；`LEVEL` 选择当前指定等级的已审核代理；`AGENT` 校验所选代理当前均为已审核状态。
4. 名单为空时拒绝发布。
5. 批量写入名单并把任务改为已发布，记录发布时间。

重复发布已发布任务直接返回当前任务，不重复生成名单；已取消任务不能重新发布。发布后代理新增、等级变化或账号禁用均不改变名单。

### 5.3 取消和结束

- 已发布任务可取消并记录取消时间；重复取消直接返回当前状态。
- 取消后不再接受后续核销进度；自然结束时间包含，取消时间不包含，避免同秒取消后的核销误计。
- 未主动取消的任务在当前时间超过 `end_time` 后显示为已结束，无需定时更新状态。
- 被禁用代理仍保留历史名单和取消/到期前已产生的进度；其后能否产生直属销售继续遵循现有代理账号规则。

## 6. 进度口径

进度只查询 `distribution_direct_sales` 中：

- `status = 1`（已核销并计入）。
- `agent_id` 等于任务名单中的代理。
- `applied_time >= start_time`。
- `applied_time <= end_time`，且任务已取消时 `applied_time < cancelled_time`。

指标计算：

- `SALES_AMOUNT`：`SUM(amount)`，单位分。
- `ORDER_COUNT`：`COUNT(*)`；直属销售表已有订单唯一键，因此每单只计一次。
- 完成状态：实时进度大于或等于 `target_value` 时为已完成，否则为未完成。
- 完成比例：`min(实时进度 / 目标值, 1)`；接口可返回百分比展示值，但不影响完成判断。

同一查询使用分组 SQL 批量计算当前页涉及的代理，禁止逐行查询。任务汇总返回名单总数、已完成人数和未完成人数；C 端只返回当前代理自己的进度。

## 7. 接口设计

### 7.1 B 端

- `GET /api/v1/distribution/tasks/page`：按名称、基础状态、展示状态、指标类型和时间查询任务，返回名单和完成汇总。
- `GET /api/v1/distribution/tasks/:id`：任务详情。
- `POST /api/v1/distribution/tasks`：新增草稿。
- `PUT /api/v1/distribution/tasks/:id`：编辑草稿。
- `DELETE /api/v1/distribution/tasks/:id`：删除草稿。
- `POST /api/v1/distribution/tasks/:id/publish`：发布并生成名单快照。
- `POST /api/v1/distribution/tasks/:id/cancel`：取消已发布任务。
- `GET /api/v1/distribution/tasks/:id/assignees/page`：按代理关键字和完成状态查询名单及实时进度。

新增权限点覆盖任务查询、创建、修改、删除、发布和取消。查看代理完成情况复用任务查询权限。

### 7.2 C 端

- `GET /api/v1/app/distribution/tasks/page`：本人任务分页，可按未开始、进行中、已结束、已取消和完成状态筛选。
- `GET /api/v1/app/distribution/tasks/:id`：本人任务详情及实时进度。

C 端通过会员 JWT 查找代理和名单，不接受客户端提交代理 ID；未分配给本人的任务返回不存在。已审核和已禁用代理可查看自己的历史任务，待审核或已驳回申请人无任务数据。

## 8. 管理端页面

新增 `src/views/distribution/task/index.vue`：

- 顶部筛选任务名称、展示状态和指标类型。
- 列表展示任务名称、指标、目标、有效期、名单数、完成人数和任务状态。
- 新增/编辑抽屉填写名称、描述、指标、目标、有效期和分配范围。
- 指定等级复用现有等级列表；指定代理复用现有代理列表并只允许选择已审核代理。
- 草稿显示编辑、删除和发布；已发布显示取消和查看完成情况；终态任务只读。
- 完成情况抽屉展示代理、当前销售额/订单数、目标、完成比例和完成状态。

销售额在页面按元输入和展示，提交时转换为整数分。页面不提供奖励、人工改完成、反馈或导出入口。

## 9. 校验、权限与失败处理

- 名称、描述、目标、时间和分配范围在 DTO 边界校验；销售额和订单数都必须大于零。
- 发布、编辑、删除和取消均在服务端校验当前基础状态，不能依赖前端按钮隐藏。
- 发布事务使用任务行锁和名单唯一键，防止并发重复发布。
- 查询软删除过滤统一沿用现有实体约定。
- B 端使用现有 RBAC；C 端使用会员 JWT，`member` 与 `sys_user` 不混用。
- 查询聚合失败只返回错误，不写任务进度，因此不会产生半完成数据。

## 10. 测试与验收

保留一个聚焦的任务规则/服务测试文件，至少覆盖：

- 全部、等级和指定代理在发布时生成固定且不重复的名单。
- 只统计直属代理、已计入且核销时间在有效期内的销售记录。
- 销售额和订单数两种目标的完成判断。
- 取消时间截断后续核销，结束时间边界正确。
- 草稿可改、发布后不可改，发布和取消可幂等重试。
- C 端不能读取未分配任务。

交付验收：

- 后端 Jest、生产构建和改动文件 ESLint 通过。
- 管理端类型检查、生产构建和改动文件 ESLint/Stylelint 通过。
- 数据库迁移、菜单权限和 UTF-8 中文名称在本地 MySQL 验证。
- 真实 HTTP 完成“创建草稿 → 发布固定名单 → 核销直属订单 → 查询完成状态 → 取消后停止累计”主链路。
- 后端和管理端保持运行，不执行会清空业务数据的全量种子脚本。

## 11. 完成标准

运营人员能创建并发布销售额或订单数任务，按全部代理、指定等级或指定代理固定名单，并实时查看每位代理的当前进度和完成状态；代理能通过 C 端接口查看本人任务；所有进度只来自有效期内的直属已核销订单，发布和取消可安全重试，系统不包含奖励、人工完成或进度流水。
